# Translation Glossary — Danish (da)

Standard Danish for Denmark. Use concise sentence case, direct imperatives and natural Danish compounds.

## Conventions

Preserve conventional numeric multiplier strings and chroma-subsampling notation as instructed by source comments. Ordinary prose uses Danish decimal commas.

Count-bearing messages use neutral labels (e.g. Resterende dage: %lld) when this avoids singular/plural agreement. Count-bearing CUBE diagnostics use neutral count labels as well, so malformed input containing exactly one entry remains grammatical.

## Retained terms

Retain brands, product names (including Tri-Screen), protocol names, API/CLI identifiers, units and abbreviations such as HDR, XDR, HiDPI, LoDPI, EDID, DisplayID, DDC, HDMI, GPU and Metal. Retain URL targets and visible domain names. Keep shortcut glyphs and printed Option/Command key names when present in source instructions. OSD denotes an on-screen indicator and remains OSD in concise labels.

Retain firmware option names (Auto Power Sync, QuickStart+, Always Ready, etc.) to help users find them on the device. Retain technical blend/filter names Screen, Overlay and Bloom; Screen here is a graphics operation, not a display. Other blend names use natural Danish graphics wording without claiming verified Apple names.

Retain chroma subsampling and graphics/protocol identifiers (Gloom, Downspread, Enhanced framing, DSC slice, CUBE, LUT, sample, compositor, overlay, regex, timeout), Core Image photo preset names Chrome/Fade/Instant/Noir/Process/Transfer, and the source example identifier My parameter. Retain Build as the technical build identifier. Common Danish words identical to English (e.g. integration, menu, model, standard, version, zone, zoom) are intentional translations.
